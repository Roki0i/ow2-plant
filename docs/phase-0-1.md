# Phase 0–1 設計・実装メモ

## スコープ

Phase 0は公開素材方式と対象マップを決定。素材・残存制約は[素材方針](asset-policy.md)を参照。
Phase 1はアプリ基盤、盤面表示、ヒーロー配置・移動、マウスとタッチによるパン・ズーム、レスポンシブUIまで。
攻防と戦術名はStrategyに格納する。保存・共有は未実装で、リロードすると消える。
Phase 2の描画ツール・削除・Undo/Redoは追加していない。線・矢印・ペンはデータ型のみ定義。

## モデルと座標

- `Strategy`は`schemaVersion: 1`、マップ・エリアID、背景の改訂番号、要素配列、攻防、日時を持つ。
- `BoardElement`は判別可能なUnion。DOMの`Element`との混同を避ける名称。
- `MapDefinition`は複数の`MapArea`に拡張可能。画像のURLをStrategyに埋め込まない。
- ローカル画像は一時的な背景。`mapRevision`を新たに生成し、寸法は画像の実寸を使用する。カタログのデモ寸法では計算しない。
- 画像変更成功時に配置を消去する。既存配置があれば事前に確認し、キャンセル・読み込み失敗では既存の背景と配置を保持。
- 正規化座標 `(u,v)` と画面座標 `(x,y)` の関係は `x = offset.x + u × image.width × scale`、`y = offset.y + v × image.height × scale`。
- 表示は縦横比を維持してフィット。配置時は画像外の余白を拒否、ドラッグ時はアイコン中心を画像端へクランプ。
- バッジは画面上で直径46 CSS pxを保ち、スマホで操作しやすくする。端の中心配置ではバッジの一部が切れる場合がある。
- 確定データはReducer、表示倍率・パン・選択・ドラッグ途中はUI側。一回のドラッグ終了時に一度だけ`move`をdispatchする。
- 拡大はフィット倍率の1〜5倍。ホイールはポインターを中心、ボタンは盤面中央を中心に拡大。
- 2本指はピンチ・パン。ヒーローのドラッグ中に2本目が触れた場合はドラッグを取り消して視点操作に切り替える。

## UIと受け入れ条件

1. 自作デモであること、対象がKing’s Row / 第1拠点であることを常時表示。
2. 9ヒーロー（各ロール3種）の文字バッジを選べる。全ヒーロー対応は未実装。
3. 味方は実線、敵は破線の枠で区別。色だけに依存しない。
4. 配置ツールでタップすると1個配置し、自動的に選択・移動へ切り替える。次の配置はヒーローまたは配置ツールを選ぶ。
5. ドラッグ、パン、ズーム、画面サイズ変更で正規化座標が破綻しない。
6. 配置一覧には名称・味方敵・座標を表示。キーボードでもヒーロー選択と配置済み座標の数値編集ができる。Canvasへの新規配置はポインター操作が必要。
7. 不正な背景ファイルを拒否し、読み込み失敗を画面表示する。

## 次Phase

- 矢印・線・フリーハンドの操作設計と描画実装。
- 選択・削除、線色と太さ、操作単位のUndo/Redo。履歴上限とフリーハンド点数削減。
- 実マップ素材の権利確認と精度検証は継続課題。デモでPhase 2の編集機能は開発可能。
- iOS SafariとAndroidの実機でピンチ・ドラッグ・スクロール競合を確認。
- モバイルのヒーロー選択をボトムシート化し、配置時の往復スクロールを減らす。
- 保存・JSON共有はPhase 3。ローカル画像の同一性、再選択、画像を含まない共有での背景不足をどう通知するかを設計する。
